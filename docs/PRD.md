# PRD · Cleaner-C（C 盘 AI 分析清理工具）

> 文档定位：**精简版产品需求**。技术实现见 [ARCHITECTURE.md](ARCHITECTURE.md)，排期见 [ROADMAP.md](ROADMAP.md)。

---

## 1. 一句话需求

给不懂技术的 Windows 用户一个工具：**能看清 C 盘被什么占满了，并且对每一项都敢给出"这是什么、能不能清、清了会怎样"的明确说法。**

## 2. 目标用户与画像

**主用户：不懂技术的普通用户**

典型特征：

- C 盘飘红、天天提示空间不足，但打开资源管理器只会看到一堆不认识的文件夹名。
- **已经或差点吃过亏**："上次用清理软件清完，微信聊天记录/照片没了"、"清完之后某软件要重新登录 / 重新下载几个 G"。
- 看到 `WinSxS`、`Installer`、`$Recycle.Bin`、`Package Cache` 这类名字完全无法判断，**不敢点**。
- 不会用命令行，不会读系统日志，也不该被要求去学。

**次要用户：愿意动手的中级用户**

- 想要一份可信的占用报告 + 明确的风险分级，能自己决定清哪些。
- 关心"是否有硬链接重复计算"这类正确性问题（现有工具普遍算错）。

**明确不服务的用户**：需要注册表优化、驱动管理、系统调优的性能发烧友 —— 那些是另一个产品。

## 3. 核心场景

| # | 场景 | 用户此刻的心理 | 工具要给出的答案 |
|---|---|---|---|
| S1 | C 盘只剩几个 G，不知道谁占的 | "到底什么东西占了这么多？" | 一张按体积铺开的图，最大的块一眼可见 |
| S2 | 看图发现一个不认识的目录 | "这玩意儿是啥？能删吗？" | 秒回本地结论：分类 + 风险等级 + 一句话解释 |
| S3 | 想删但怕出问题 | "删了会怎样？那些东西会不会一起没？" | AI 展开讲：关联什么内容、影响什么、能否回滚、预期回收多少 |

## 4. 功能清单

### P0 —— 没有它产品不成立（M1 / M2）

| 功能 | 说明 |
|---|---|
| 只读全盘扫描 | 扫描 C 盘目录树，统计每个目录/文件的体积；**全程不写盘、不删改任何文件** |
| Treemap 占用可视化 | 面积 = 体积，支持逐层下钻；最大占用项视觉上一眼可见 |
| 悬浮本地规则解释 | 悬浮即显示：这是什么、分类、风险等级、是否建议清理、为什么。**必须 0 延迟、0 token** |
| 点击 AI 深入解释 | 用户主动点击才调用模型，给出关联内容、影响面、可回滚性、建议与预期收益 |
| BYOK 设置页 | 只需填写 baseURL + apiKey；含连通性自检与失败原因区分；**`GET` 永不回传明文 Key** |
| 模型自动发现与选择 | 填入地址与 Key 后**自动拉取可用模型列表供下拉选择，无需手填模型 ID**；列表接口不可用时自动回退手填，**不阻断配置流程** |
| 模型测速 | 对候选模型测 TTFT / 总延迟 / 生成速度（TPS）/ 结构化输出通过率，辅助"又快又省"选型；执行前明确告知 token 消耗 |
| 扫描进度与取消 | 实时进度（文件数、已扫体积、当前路径），可随时中断 |
| 扫描完整性诚实披露 | 明确显示"有 N 个目录因权限未能读取"，**不得静默给出偏小的数字** |

### P1 —— 让工具敢用、可复现（M3）

| 功能 | 说明 |
|---|---|
| 删除到回收站 | **只走回收站，不提供永久删除**；删除前列出精确清单与总大小 |
| 清理前后对比 | 前后体积对比，验证实际回收了多少（对不上要说明原因） |
| 报告导出 | 导出 md（给人看）/ json（给机器读）的扫描与建议报告 |
| 白名单 | 用户标记"这些目录永远别提示我清理" |
| 高危项二次确认 | 系统目录、程序安装目录、用户文档目录需额外确认步骤 |

### P2 —— 锦上添花（M4）

管理员提权模式（补齐权限盲区）、目录快照对比（看增长趋势）、MFT 加速、**免安装分发封装**（用户零运行时安装；具体形态在 M2 末尾确定）。

## 5. 明确不做的事（反向清单）

这些是**刻意的边界**，不是"以后再说"：

- ❌ **注册表清理** —— 收益小、风险高、误伤面大，且无法可靠回滚。
- ❌ **驱动更新 / 系统优化 / 性能调优** —— 另一个产品的问题域。
- ❌ **自动清理 / 定时清理 / 一键全清** —— 与"先解释、再决定"的核心原则直接冲突。
- ❌ **上传文件内容到云端** —— 只发路径模板与统计量，内容永不出本机。
- ❌ **修改系统设置的"一键优化"** —— 用户无法预知后果的隐式修改一律不做。
- ❌ **承诺"清得最干净"** —— 本工具的卖点是**不误删**，不是清得最多。
- ❌ **要求用户自行安装 Node / Python 等运行时** —— 目标用户装不了也不该装；分发必须开箱即用（见 [ARCHITECTURE.md](ARCHITECTURE.md) §10）。

## 6. 关键交互流程

**流程 A：首次使用（无 Key）**
启动 → 扫描（进度 + 取消）→ Treemap 展示 → 悬浮看本地解释 → 导出报告 → 结束。
> 全程不出现"请先配置 API Key"的阻断式引导；Key 是可选的增强项。

**流程 B：追问 AI**
点击某一项 → 侧栏显示【本地结论（立即）】+【AI 深入解读（加载中）】→ AI 返回结构化结果（关联内容 / 影响面 / 可回滚性 / 建议 / 预计收益）。
> 若未配置 Key 或请求失败：侧栏保留本地结论，并明确标注"AI 解读不可用（原因）"，**不让用户面对空白或看起来像加载失败的界面**。

**流程 C：清理（M3）**
勾选 → 预检（列出精确文件清单 + 总大小 + 风险项）→ 二次确认 → 删除到回收站 → 结果对比报告。

## 7. 成功指标（可测量）

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 全盘只读扫描耗时 | 100 GB 数据量 ≤ **60 s** | M1 在实测基线上计时 |
| 占用统计准确性 | 与 WizTree/WinDirStat 对照误差 < **2%**（硬链接去重后） | 交叉比对同一目录 |
| 权限失败可见性 | 未授权目录 **100%** 被报告 | 按实测的 EPERM 目录核对 |
| AI 解释可用性 | 主观准确率 ≥ **4/5**（人工抽样评分） | 抽样评审 |
| **误删高危路径** | **= 0** | 高危路径必须走二次确认，不可绕过 |
| 无 Key 可用性 | 核心功能 **100%** 可用 | 关闭 Key 走通流程 A |
| 单次解释成本 | 可量化、可预算（按 token 计） | 网关侧计量 + 缓存命中率 |
| 模型配置上手成本 | 填入 baseURL + Key 后**无需手查模型 ID**，≤ 3 步完成配置 | 新人可用性测试 |

## 8. 主要风险与应对

| 风险 | 应对 |
|---|---|
| **AI 幻觉导致误导用户删错** | 安全性由本地规则表决定；AI 只解释、不判定；高危等级不允许 AI 降级 |
| 扫描结果偏差（硬链接、权限） | 见架构文档"正确性陷阱"；偏差必须显式披露而非隐藏 |
| API Key 泄露 | 仅本地存储、不进日志、不进导出报告；请求体不包含任何文件内容 |
| 模型成本失控 | 本地规则兜底 + 结果按规则指纹缓存 + AI 仅点击触发 |
| 用户仍误删 | 删前清单 + 二次确认 + 回收站 + 报告留痕，四道闸 |
| 范围膨胀 | 每阶段配"明确不做"反向清单（见 ROADMAP） |

## M1 · 看得清（只读扫描 + 可视化 + 本地规则）

> **结构变更**：M1 拆为 **M1a（内核 + 门禁）** 与 **M1b（UI）**。原因：扫描内核的精度与性能是高风险项，**必须先通过自动化门禁再做界面** —— 否则一旦内核不达标，UI 上的工作量会白费。

**目标**：用户能在一分钟内看到 C 盘被什么占满了，并且对每一项都能立刻得到一个**不依赖任何 API Key** 的本地结论。

### M1a · 扫描内核 + 规则引擎 + 门禁

**交付物**

- 扫描内核（`core-scan`）：有界并发（实测最佳 **32 workers / stat 128**）+ 背压；物理/逻辑双口径；**BigInt 键硬链接去重**；junction 不跟随；权限失败收集清单。
- **回收站识别走 Shell COM API**（`Shell.Application.NameSpace(10)`）—— 目录遍历读不到（实测 EPERM）。
- 规则引擎（`core-rules`）+ 首批规则库：按架构 §4.3 的**用户目录优先**顺序；风险四级（safe/caution/risky/system）；未知项默认 `caution`；**聚合节点**（`Users`、`ProgramData` 等混合内容）需给出"混合内容"摘要而非单一结论。
- SQLite 索引（`node:sqlite`）+ 聚合树接口 + **扫描结果缓存**（复用上次结果，支持增量重扫）。
- **CLI + 精度/性能 harness**：把本次探测脚本（全盘扫描 / 并发扫描 / 硬链接去重 / 元数据探测 / 目录分解）升级为可复跑的门禁测试。
- **差额分解披露**：逻辑口径、物理口径、磁盘已用三者之间的差额逐项解释（硬链接共享、未授权目录、系统独占文件）。

**验收标准（门禁）**

| # | 标准 | 测量方式 |
|---|---|---|
| 1 | **首屏可用 ≤ 15 s**：先出顶层目录与主要占用项，全盘后台继续 | 冷启动计时（NVMe 基线） |
| 2 | **全盘 75 万文件级目录树 ≤ 120 s**（后台完成、可取消） | 对照附录 A.5 实测（最佳 87.8 s，留余量） |
| 3 | **缓存复用重开 ≤ 3 s** | 二次启动计时 |
| 4 | 占用统计与 PowerShell / WizTree 对照**误差 < 2%**（硬链接去重后） | 交叉比对；**差异必须能解释** |
| 5 | **跨目录硬链接去重生效**：`System32 + WinSxS` 合并时逻辑 19.41 → 物理 16.25 GB | 对照附录 A.6 |
| 6 | 未授权目录 **100%** 被记录（实测 **219 个**） | 对照附录 A.4 |
| 7 | 回收站**可见**（2.28 GB / 2,140 项） | Shell API 枚举验证 |
| 8 | **差额分解**：逻辑 / 物理 / 已用三者缺口有逐项解释 | 对照附录 A.6 |
| 9 | **全程零写入**（文件时间戳/哈希抽查） | 抽查验证 |
| 10 | **不配置任何 Key 即可完整走通** | 断网 + 空配置测试 |

### M1b · 可视化与交互

**交付物**

- 本地 HTTP 服务（仅回环）+ SSE 流式进度 + 取消。
- 前端：Treemap（面积 = 体积，可下钻，**硬链接共享字节进入"余量桶"以保证面积守恒**）、悬浮本地规则卡（**0 延迟 / 0 token**）、扫描进度条、未授权目录常驻提示。

**验收标准**

| # | 标准 |
|---|---|
| 11 | **Treemap 面积守恒**：子项之和 == 父项（含余量桶） |
| 12 | 悬浮即出本地结论，**无任何网络请求**（离线可复现） |
| 13 | 未授权目录与差额分解在 UI 中**常驻可见** |
| 14 | 不存在的系统项显示"未发现"而非"0 GB"（对照附录 A.3） |

**明确不做**：不接 AI（哪怕一行）、不做删除、不做提权、不做 MFT、不做桌面壳、不做注册表/驱动/系统优化。

> **性能目标的取舍说明（重要）**：本文件此前要求"100 GB ≤ 60 s"，**实测证明该指标双重错误** —— ① **量纲错**：成本由文件/目录数量驱动，与字节数无关（142.81 GB / 87.8 s）；② **60 s 在纯 Node + NVMe 下不可达**：极限约 88 s，且提高并发无收益（96 并发更慢）。若产品上坚持 60 s，**必须把 MFT 拉进 M1**（当前列于 M4）。本修订选择"改为可达的分层目标"并保留 MFT 于 M4；如需 60 s，请在此处调整范围。

**主要风险（含实测依据）**

| 风险 | 实测依据 | 应对 |
|---|---|---|
| 速度不达标 | 最佳 87.8 s；**96 并发反而 95.1 s** | 已达纯 Node 上限；如需更快只能上 MFT |
| 并发调参无效 | 32/128 最优，96/384 更慢 | 不再追求更高并发，转而优化枚举路径 |
| AV 实时扫描干扰 | 杀软开启下测得 | 门禁记录杀软状态；结果按环境标注 |
| 介质差异 | 本机为 NVMe SSD | HDD 上并发收益大降 → 目标按介质分档，门禁记录介质类型 |
| 精度 | `ino` 2.36e16 超安全整数 | 强制 BigInt；harness 覆盖该用例 |
| 检不出重复计算 | WinSxS 单独虚高仅 1.3% | **测试对象必须选跨目录共享的父目录**（System32+WinSxS） |

## M2 · 讲得明（AI 解释 + 缓存 + 降级）

**目标**：用户主动追问时，AI 能给出"关联什么、影响什么、能否回滚、建议怎么做"的大白话解释，且**在没有任何 Key 的情况下产品体验依然完整**。

**交付物**

- `core-ai`：Provider 抽象（OpenAI 兼容为基准，含 DeepSeek / Anthropic / Gemini / Ollama 适配）、结构化 JSON 输出 + 本地 schema 校验、越权钳制、超时与降级链、按规则指纹缓存、token 计量。
- 设置页：只需填 `baseURL` + `apiKey`，**自动拉取可用模型列表供下拉选择（不必手查模型 ID）**；含连通性自检、失败原因区分、手填兜底、本地/云端切换、"完全离线模式"开关、一键清除密钥。
- **模型测速**：对候选模型测 TTFT / 总延迟 / 生成速度（TPS）/ 结构化输出通过率；执行前明确告知 token 消耗；结果仅本地缓存。
- **分发形态定稿（M2 末尾必须完成）**：确定"终端用户零运行时安装"的打包路径；M1 起即以 `node:sqlite` 为默认实现，避免原生模块阻塞打包（见 [ARCHITECTURE.md](ARCHITECTURE.md) §10）。
- 前端：点击节点 → 侧栏并排展示【本地结论】与【AI 深入解读】，标注来源与缓存命中状态。

**验收标准**

| # | 标准 | 测量方式 |
|---|---|---|
| 1 | **Key 泄露面 = 0**：日志、导出报告、错误信息中均不出现明文密钥 | 全量搜索日志与导出文件 |
| 2 | 请求体不含文件内容与隐私路径 | 抓包/拦截审查请求负载 |
| 3 | 无 Key 或断网时，核心功能 **100%** 可用，且给出明确的"为什么没有 AI 解释" | 断网 + 空配置测试 |
| 4 | 模型建议**永不比本地规则更激进**（系统级项不能被改口为"可删"） | 构造对抗性用例测试 |
| 5 | `expectedReclaimGB` 不超过本地物理大小，超出即被钳制 | 构造幻觉用例测试 |
| 6 | 同类节点的重复追问命中缓存，**不重复计费** | 缓存命中率统计 |
| 7 | 单次解释的 token 成本可量化、可在设置页查看累计用量 | 计量面板 |
| 8 | 解释质量主观评分 ≥ 4/5（抽样） | 人工抽样评审 |
| 9 | 填入 baseURL + Key 后**自动列出可用模型**，无需手填模型 ID | 对 OpenAI 兼容端点与 Ollama 实测 |
| 10 | 模型列表接口不可用时**自动回退手填**，不阻断配置流程 | 构造 401 / 404 / 超时 / 非 JSON 响应用例 |
| 11 | 测速给出 TTFT / TPS / 结构化输出通过率，且**执行前提示 token 消耗** | 多模型实测 |
| 12 | **分发形态已定稿**，且已实测"零运行时安装"可跑通 | 在剥离 Node 的 PATH 环境实测产物 |

**明确不做**：不自动触发 AI（必须用户点击）、不把模型输出当可执行动作、不上传文件内容、不做多轮对话式 Agent、不做微调/自建模型；**本阶段只定分发方案、不做最终封装实现**（实现归 M4）。

**主要风险**：模型幻觉（对应措施：规则前置 + schema 校验 + 越权钳制）；成本失控（对应措施：点击触发 + 指纹缓存 + 计量可见）；用户以为"没 AI 就不能用"（对应措施：无 Key 时 UI 明确说明本地结论已完整）。

## M3 · 敢动手（安全清理）

**目标**：让用户敢按下"清理"，并且**事后一定能回头**。

**交付物**

- 清理预检：列出精确文件清单 + 总大小 + 风险项标注。
- **仅删除到回收站**（任何版本都不提供永久删除），支持从回收站撤销。
- 高危路径二次确认（系统目录、程序安装目录、用户文档目录），**不可绕过**。
- 白名单（用户标记"永不提示清理"）。
- 清理前后体积对比 + 对不上时的原因说明。
- 报告导出：md（给人看）/ json（给机器读），含未授权目录清单与本次未执行项。

**验收标准**

| # | 标准 | 测量方式 |
|---|---|---|
| 1 | 全流程可回滚：删除后可完整撤销恢复 | 端到端演练 |
| 2 | 高危路径**必然**触发二次确认，且无法通过任何 UI 路径跳过 | 用例遍历 |
| 3 | `system` 级永远不可被标记为"可清理" | 规则库全量校验 |
| 4 | 导出报告中不含明文密钥 | 检查导出物 |
| 5 | 实际回收体积与预检估算的差异有明确解释 | 对比报告核对 |
| 6 | **误删高危路径 = 0** | 全量用例回归 |

**明确不做**：不做永久删除、不做自动/定时清理、不做"一键清理全部"入口、不清理用户文档域、不清理注册表。

## M4 · 更快更省事（加速 + 提权 + 封装决策）

**目标**：补齐性能与权限盲区，并决定最终分发形态。

**交付物**

- **MFT 加速**（`FSCTL_ENUM_USN_DATA`）：目标秒级全盘扫描；实现方式在 .NET sidecar（本机已装 SDK 10.0.302）与 Rust native 模块之间二选一，并保留纯 Node 回退路径。
- 管理员提权模式：补齐非管理员读不到的目录，重新出具完整度更高的报告（并明确标注本次是否完整）。
- 目录快照对比：看增长趋势，回答"这周是什么在涨"。
- **免安装分发实现**：按 M2 末尾定稿的形态落地（单文件 exe / Tauri / 自包含 .NET / Electron），含安装包与签名、自动更新、卸载入口、首次启动的防火墙与杀软提示、端口占用与单实例。

**验收标准**：MFT 路径结果与 Node 路径**逐目录一致**（差异可解释）；提权后未授权目录数显著下降并如实报告；壳层封装后核心内核零改动（验证分层边界成立）。

**明确不做**：不为性能牺牲统计正确性（硬链接去重与权限披露在任何模式下都必须保留）；不引入联网上报。

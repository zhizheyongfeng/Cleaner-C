## M1 · 看得清（只读扫描 + 可视化 + 本地规则）

> **结构变更**：M1 拆为 **M1a（内核 + 门禁）** 与 **M1b（UI）**。原因：扫描内核的精度与性能是高风险项，**必须先通过自动化门禁再做界面** —— 否则一旦内核不达标，UI 上的工作量会白费。

**目标**：用户能在**数秒内**看到 C 盘被什么占满了，并且对每一项都能立刻得到一个**不依赖任何 API Key** 的本地结论。

### M1a · MFT 扫描内核 + 规则引擎 + 门禁

**交付物**

- **MFT 扫描内核（`CleanerC.Scan`，C#）**：卷访问（`\\.\C:`，需提权）、引导扇区解析、run list、**扇区对齐读取**、记录流式解析、USA 修复。
- **硬链接去重（按 FRN）+ DOS 8.3 别名过滤**：输出物理 / 逻辑双口径。
- **孤儿记录三级回退**：父指针为 0 时按 ① 其它 `$FILE_NAME` 项 → ② `$I30` 目录索引 → ③ 目录遍历补全（架构 §3.3(3)）。
- **单文件双模式入口 + 按需自提权**：清单 `asInvoker`（启动**不**弹 UAC）；点「开始扫描」时先展示说明，再 `runas` 自我提权为扫描器角色（`--scanner --pipe <随机名>`），**仅只读**、完成后退出。
- **命名管道 IPC**：宿主（非提权）= 服务端，扫描器（提权）= 客户端；回传**进度 + 结果分块**；管道名随机化并校验对端。
- **UAC 拒绝处理**：点"否"（`ERROR_CANCELLED`）、标准用户、企业策略禁用提升 → 明确说明并终止该次扫描，**不崩溃、无残留提权进程**。
- 规则引擎 + 首批规则库：按架构 §4.3 的**用户目录优先**顺序；风险四级；未知项默认 `caution`；聚合节点给"混合内容"摘要。
- SQLite（**Microsoft.Data.Sqlite**）索引 + 聚合树接口 + 扫描结果落库。
- **门禁测试 harness**：把本次 MFT spike（含双口径统计与归属诊断）升级为可复跑测试。
- **差额分解披露**：文件 / 索引 / 元数据 / 命名流 / 未归属 五类分解。
- **提权模式只读约束**：不接受写 / 删除 / 执行类指令或参数；目标卷限定系统盘（安全要求，见架构 §8、§11）。

**验收标准（门禁）**

| # | 标准 | 测量方式 |
|---|---|---|
| 1 | **全盘扫描 ≤ 5 s**（本机 989,696 条记录） | 对照附录 A.5 实测（**2.19 s**，留余量） |
| 2 | 记录/占用与 WizTree、PowerShell 对照**误差 < 2%** | 交叉比对；差异必须能解释 |
| 3 | **物理 / 逻辑双口径正确**：物理 **117.92 GB**、逻辑（真实名）**122.60 GB** | 对照附录 A.6 |
| 4 | **DOS 别名过滤生效**：含别名口径 **185.26 GB** 不得被当作逻辑口径输出 | 对照附录 A.6 |
| 5 | **硬链接去重生效**：物理文件 **724,225**（而非目录项 757,385） | 对照附录 A.6 |
| 6 | **孤儿记录有归属或显式披露**：**45.59 GB** 未归属必须消除或明确分类 | 对照附录 A.6 |
| 7 | **差额分解**：145.13 − 117.92 = **27.21 GB** 有逐项解释 | 对照架构 §3.4 |
| 8 | 回收站**可见**（2.28 GB / 2,140 项） | MFT + `$I*` / Shell API 验证 |
| 9 | **按需提权路径**：启动不弹 UAC；点扫描时弹且弹前有说明；提权成功即扫描 | 管理员 / 标准用户各测一次 |
| 9b | **UAC 被拒 → 明确提示、不崩溃、无残留提权进程**；宿主继续可用 | 手动点"否"后检查进程与界面 |
| 9c | **提权模式参数面为只读**（不接受写/删/执行类入参） | 代码审查 + 构造非法参数用例 |
| 10 | **全程零写入**（时间戳 / 哈希抽查） | 抽查验证 |
| 11 | **不配置任何 Key 即可完整走通** | 断网 + 空配置测试 |

### M1b · 可视化与交互

**交付物**

- **ASP.NET Core 宿主**（仅回环）+ 静态资源托管 + SSE 流式进度 + 取消。
- 前端：Treemap（面积 = 体积，可下钻，**共享字节进"余量桶"以保证面积守恒**）、悬浮本地规则卡（**0 延迟 / 0 token**）、进度、**未归属与差额分解常驻可见**。

**验收标准**

| # | 标准 |
|---|---|
| 12 | **Treemap 面积守恒**：子项之和 == 父项（含余量桶） |
| 13 | 悬浮即出本地结论，**无任何网络请求**（离线可复现） |
| 14 | 未归属分类与差额分解在 UI 中**常驻可见** |
| 15 | NTFS 元数据文件（`$MFT` / `$LogFile` 等）**不进入"可清理"候选** |
| 16 | 不存在的系统项显示"未发现"而非"0 GB" |

**明确不做**：不接 AI（哪怕一行）、不做删除、不做桌面壳、不做注册表 / 驱动 / 系统优化、**不做慢速回退、不做非 NTFS 卷支持**。（**提权与 MFT 已进入 M1a 范围**，不再是"不做"项。）

> **性能目标的历史沿革（供追溯）**：本文件最初要求"100 GB ≤ 60 s"，被实测证明**双重错误**（① 量纲错：成本由记录数驱动，与字节数无关；② 数值不可达：纯 Node 极限 87.8 s）。随后改为"首屏 15 s / 全盘 120 s"的分层目标，并把 MFT 放在 M4。**现因 MFT 实测成功（2.19 s / 989,696 条记录），MFT 提前进入 M1，目标收敛为"全盘 ≤ 5 s"** —— 原分层目标与"60 s 之争"一并作废。

**主要风险（含实测依据）**

| 风险 | 实测依据 | 应对 |
|---|---|---|
| **提权被拒 / 标准用户 / 企业策略禁止提升** | 非管理员 `Win32Error=5`；点"否" → `ERROR_CANCELLED` | 明确说明原因并终止该次扫描；**不静默降级、不做慢速回退** |
| **提权助手成为权限提升面** | — | 提权模式**只读**（拒绝写/删/执行类参数）、参数面固定、目标限定系统盘；**M3 删除不走此通道**（架构 §8、§11） |
| 孤儿记录导致归属失败 | 11,455 条 → **45.59 GB** 未归属 | 三级回退（`$FILE_NAME` → `$I30` → 目录遍历） |
| DOS 别名虚高 | 642,368 条别名 → 虚高 **51%** | 强制 ns≠2 过滤；harness 覆盖 |
| 差额无法解释 | **27.21 GB** 待分解 | 差额分解列为门禁项，未解释不算通过 |
| 非 NTFS 卷 | 未测（本机为 NTFS） | **不支持**：明确报错（本次决策移除回退；不做目录遍历实现） |
| 大卷性能 | 仅本机 989,696 条 | 门禁记录卷规模与介质；更大卷需复测 |
| AV 实时扫描 / 介质差异 | 杀软开启下测得 | 门禁记录杀软状态与磁盘类型 |

## M2 · 讲得明（AI 解释 + 缓存 + 降级）

**目标**：用户主动追问时，AI 能给出"关联什么、影响什么、能否回滚、建议怎么做"的大白话解释，且**在没有任何 Key 的情况下产品体验依然完整**。

**交付物**

- `core-ai`：Provider 抽象（OpenAI 兼容为基准，含 DeepSeek / Anthropic / Gemini / Ollama 适配）、结构化 JSON 输出 + 本地 schema 校验、越权钳制、超时与降级链、按规则指纹缓存、token 计量。
- 设置页：只需填 `baseURL` + `apiKey`，**自动拉取可用模型列表供下拉选择（不必手查模型 ID）**；含连通性自检、失败原因区分、手填兜底、本地/云端切换、"完全离线模式"开关、一键清除密钥。
- **模型测速**：对候选模型测 TTFT / 总延迟 / 生成速度（TPS）/ 结构化输出通过率；执行前明确告知 token 消耗；结果仅本地缓存。
- **分发形态已定稿**：自包含单文件 .NET（实测控制台基线 **37.58 MB**），用户零运行时安装；M2 仅需定 ① 默认浏览器 or WebView2 壳 ② 安装包形式 ③ 签名与自动更新（见 [ARCHITECTURE.md](ARCHITECTURE.md) §10）。
- 前端：点击节点 → 侧栏并排展示【本地结论】与【AI 深入解读】，标注来源与缓存命中状态。

**验收标准**

| # | 标准 | 测量方式 |
|---|---|---|
| 1 | **Key 泄露面 = 0**：日志、导出报告、错误信息中均不出现明文密钥 | 全量搜索日志与导出文件 |
| 2 | 请求体不含文件内容与隐私路径 | 抓包/拦截审查请求负载 |
| 3 | 无 Key 或断网时，核心功能 **100%** 可用，且给出明确的"为什么没有 AI 解释" | 断网 + 空配置测试 |
| 4 | 模型建议**永不比本地规则更激进**（系统级项不能被改口为"可删"） | 构造对抗性用例测试 |
| 5 | `expectedReclaimGB` 不超过本地物理大小，超出即被钳制 | 构造幻觉用例测试 |
| 6 | 同类节点的重复追问命中缓存，**不重复计费** | 缓存命中率统计 |
| 7 | 单次解释的 token 成本可量化、可在设置页查看累计用量 | 计量面板 |
| 8 | 解释质量主观评分 ≥ 4/5（抽样） | 人工抽样评审 |
| 9 | 填入 baseURL + Key 后**自动列出可用模型**，无需手填模型 ID | 对 OpenAI 兼容端点与 Ollama 实测 |
| 10 | 模型列表接口不可用时**自动回退手填**，不阻断配置流程 | 构造 401 / 404 / 超时 / 非 JSON 响应用例 |
| 11 | 测速给出 TTFT / TPS / 结构化输出通过率，且**执行前提示 token 消耗** | 多模型实测 |
| 12 | **分发形态已定稿**，且已实测"零运行时安装"可跑通 | 在**无 .NET 运行时的环境**下实测自包含产物 |

**明确不做**：不自动触发 AI（必须用户点击）、不把模型输出当可执行动作、不上传文件内容、不做多轮对话式 Agent、不做微调/自建模型；**本阶段只定分发方案、不做最终封装实现**（实现归 M4）。

**主要风险**：模型幻觉（对应措施：规则前置 + schema 校验 + 越权钳制）；成本失控（对应措施：点击触发 + 指纹缓存 + 计量可见）；用户以为"没 AI 就不能用"（对应措施：无 Key 时 UI 明确说明本地结论已完整）。

## M3 · 敢动手（安全清理）

**目标**：让用户敢按下"清理"，并且**事后一定能回头**。

**交付物**

- 清理预检：列出精确文件清单 + 总大小 + 风险项标注。
- **仅删除到回收站**（任何版本都不提供永久删除），支持从回收站撤销。
- 高危路径二次确认（系统目录、程序安装目录、用户文档目录），**不可绕过**。
- 白名单（用户标记"永不提示清理"）。
- 清理前后体积对比 + 对不上时的原因说明。
- 报告导出：md（给人看）/ json（给机器读），含未授权目录清单与本次未执行项。

**验收标准**

| # | 标准 | 测量方式 |
|---|---|---|
| 1 | 全流程可回滚：删除后可完整撤销恢复 | 端到端演练 |
| 2 | 高危路径**必然**触发二次确认，且无法通过任何 UI 路径跳过 | 用例遍历 |
| 3 | `system` 级永远不可被标记为"可清理" | 规则库全量校验 |
| 4 | 导出报告中不含明文密钥 | 检查导出物 |
| 5 | 实际回收体积与预检估算的差异有明确解释 | 对比报告核对 |
| 6 | **误删高危路径 = 0** | 全量用例回归 |

**明确不做**：不做永久删除、不做自动/定时清理、不做"一键清理全部"入口、不清理用户文档域、不清理注册表。

## M4 · 更快更省事（企业适配 + 快照 + 分发实现）

> **范围变更**：原 M4 的两大项（**MFT 加速**、**提权**）**已提前进入 M1a**（因 MFT 实测成功）。M4 只保留剩余的收尾工作。

**目标**：完成分发实现，并处理 MFT 在真实环境中的边界情况。

**交付物**

- **分发实现**：按 M2 定稿形态落地（自包含单文件 + 安装包），含**代码签名**、自动更新、卸载入口、首次启动的杀软 / 防火墙提示、端口占用与单实例。
- **提权边界适配**：标准用户账户与企业策略禁用 UAC 提升场景的说明与一致性行为；（**不做**慢速回退，见 M1a）。
- **目录快照对比**：看增长趋势，回答"这周是什么在涨"。
- **大卷 / HDD 实测**：在更大卷与 HDD 上复测 MFT 性能并如实标注（**不做**非 NTFS 支持）。

**验收标准**：安装包在**干净机器**（无 .NET）上双击可用；启动不弹 UAC、点扫描才弹；UAC 被拒时有明确说明而非崩溃；更大卷上性能如实标注（不承诺固定秒数）；快照对比结果可复查。

**明确不做**：不为性能牺牲统计正确性（硬链接去重、DOS 别名过滤、差额分解在任何模式下都必须保留）；不引入联网上报。

# Cleaner-C · C 盘 AI 分析清理工具

> 扫描 C 盘 → 可视化看到"到底是谁占了我的空间" → 悬浮或点击任意一项，AI 用大白话告诉你：**这是什么、能不能清、清了会发生什么。**

> 当前阶段：**规划中，尚无代码。** 本仓库目前只包含开发前文档。

---

## 1. 为什么做这个工具

CCleaner 这类工具"有效果"，但它的工作方式是**黑箱勾选 + 一键清理**：

- 你不知道它勾中的那 300 MB 到底是什么，只能相信它"是垃圾"。
- 清完才发现：微信/QQ 的聊天记录被删了、浏览器保存的登录状态没了、某软件的离线数据被清了要重新下载。
- 对不懂技术的用户来说，**风险不在于没清干净，而在于清掉了不该清的**。

WizTree / WinDirStat 解决了另一半问题：扫得快、看得清，但它们只告诉你**"这里占了 8 GB"**，不告诉你**"这 8 GB 是什么、该不该动"**。

本工具要补的正是中间那一段：**把"看不懂的文件"翻译成"看得懂的取舍"。**

## 2. 核心设计原则

| 原则 | 含义 |
|---|---|
| **先解释，再决定** | 每一项都有本地规则给出的结论，用户看完解释再自己拍板 |
| **默认不动手** | v0.1 全程只读，扫描不会修改磁盘上的任何内容 |
| **规则判定在前，AI 解释在后** | 安全性由本地规则表决定，AI 只负责"讲人话"，不负责判断能不能删 |
| **AI 不是必需品** | 不配置任何 API Key，工具的核心功能依然 100% 可用 |
| **数据不出本机** | 只把"路径模板 + 分类 + 大小"发给模型，**绝不发送文件内容** |

## 3. 与现有工具的差异

| | CCleaner 类 | WizTree / WinDirStat | **本工具** |
|---|---|---|---|
| 扫描速度 | 快 | 极快（MFT 直读） | **极快：直读 NTFS `$MFT`，实测 2.19 s 完成 98.9 万条记录**（详见 [架构文档](docs/ARCHITECTURE.md) §3） |
| 占用可视化 | 无 | 优秀 | 优秀（Treemap，面积 = 占用） |
| 逐项解释 | 无 | 无 | **有：本地规则 + AI 双通道** |
| 是否告诉你"删了会怎样" | 无 | 无 | **有：风险评估 + 关联内容 + 可回滚性** |
| 首次使用风险 | 高（一键清） | 无（只读） | **低（只读起步，删除走回收站）** |

│  │    可回滚：部分可回滚（需 DISM）                       │  │

> 图中数值取自本机真实全盘实测（`Users` 84.52 GB / `Windows` 29.69 GB / `Program Files` 11.74 GB / `WinSxS` 9.99 GB / 回收站 2.28 GB / 未授权目录 219 个），非示意数字 —— 详见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) 附录 A。
>
> 注意回收站那一条：它**无法通过目录遍历读到**（权限拒绝），必须走 Shell API —— 否则最典型的可清理项会被整块漏掉。

**为什么要分两层**：悬浮是全盘最高频的交互，若每次都请求模型，既慢又烧钱。所以**本地规则表负责"秒回的结论"，AI 只在用户主动追问时负责"展开讲透"**。这也是本工具控制成本的核心设计。

## 5. BYOK —— 自带 Key，开源项目不碰你的数据

本工具**不内置任何 API Key、不提供任何代理服务、不上传你的文件内容**。模型能力完全由使用者自己接入：

| 方式 | 说明 |
|---|---|
| OpenAI 兼容接口 | 默认基准，一份配置适配绝大多数国内外服务与自建网关 |
| 主流云模型 | DeepSeek / 阿里通义 / 智谱 / Moonshot / Anthropic / Gemini 等 |
| 本地模型 | Ollama、LM Studio 等本地 endpoint（完全离线，零外发） |
| **不配置** | **功能降级为纯本地规则库，核心流程依然完整可用** |

密钥仅保存在本机用户配置文件中，不写日志、不进报告、不出现在任何导出文件里。

**配置体验（对小白友好）**：只需填「模型地址 + Key」两栏 —— 工具会自动拉取该地址下的可用模型列表供下拉选择，**不必手查模型 ID**；并提供**模型测速**（首字节时间 / 生成速度 TPS / 结构化输出通过率），让你在多个模型之间用数据挑一个又快又省的。模型列表与测速结果仅存本地。

## 7. 关于仓库本身

- 定位：**开源项目**，鼓励使用者自行填写模型 Key 与 endpoint。
- **分发原则**：终端用户**不需要安装任何运行时**（不需要 .NET、不需要 Node）。实测：.NET 自包含单文件产物 **37.58 MB**，可直接运行 —— 详见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) §10。
- **权限前提（重要）**：**启动不提权**（双击即用，不弹 UAC）。只有当你点【开始扫描】时，才会**先说明原因再请求管理员权限** —— 因为读取磁盘索引（NTFS `$MFT`）需要它，这也是把扫描从 2 分钟缩短到 2 秒的原因。提权仅用于**只读扫描**，扫描结束即退出；界面、网络服务与 AI 网关**始终以普通权限运行**。
- **如实披露的限制**：① 若你拒绝授权、或账户非管理员、或企业策略禁用提权，**扫描功能不可用**（会明确说明，不静默失败、不降级为慢速扫描）；② 仅支持 **NTFS** 卷（系统盘都是 NTFS；外接的 exFAT U 盘不支持）。
- 项目名称：**Cleaner-C**（已定，与 GitHub 仓库同名）。
- 仓库地址：<https://github.com/zhizheyongfeng/Cleaner-C>
- **技术栈**：后端 **.NET 10 / ASP.NET Core**（MFT 扫描内核、规则引擎、AI 网关）+ 前端 **Vite / React / TypeScript**；**单文件双模式**（同一 exe 既作非提权宿主，也作按需提权的只读扫描器），两者经**命名管道**通信；SQLite（Microsoft.Data.Sqlite）。
- 开源协议：**[MIT](LICENSE)**（已定）。
- 本仓库当前**不含产品代码**；已完成 M0 规划文档与一个 **MFT 直读原型（spike）**，后者将作为 M1a 扫描内核的骨架。
